# Lovable Web Knowledge

A practical operating system for building high-quality websites and web apps with Lovable.

This repository is intentionally split into two layers:

1. **Workspace Knowledge** — permanent rules that should apply to every Lovable project.
2. **Workspace Skills** — specialized instructions that should activate only when relevant.

## Recommended Lovable setup

Paste `LOVABLE-WORKSPACE-KNOWLEDGE.md` into **Settings → Knowledge**.

Import the folders under `skills/` as workspace skills.

## Skill map

- `website-project-orchestrator` — end-to-end website creation and redesign workflow.
- `discovery-positioning` — client discovery, ICP, offer, differentiation, competitor research.
- `copywriting-cro` — conversion copy, page structure, CTA, proof, objections, product pages.
- `premium-web-design` — art direction, design systems, visual hierarchy, responsive quality.
- `frontend-engineering` — implementation standards for React/TypeScript/Tailwind/shadcn projects.
- `seo-discoverability` — technical/on-page/local SEO, structured data, AI discoverability.
- `ecommerce-saas-local` — specialized patterns for ecommerce, SaaS and local-service sites.
- `marketing-growth` — ads, email, launch, analytics and experimentation.
- `qa-accessibility-performance` — testing, accessibility, mobile QA and performance.
- `design-reference-system` — visual-reference routing and anti-copy synthesis.
- `advanced-ecommerce-cro` — product pages, carts, offers, bundles and mobile ecommerce conversion.
- `local-business-seo` — local-service architecture, location pages, trust and qualified local leads.
- `saas-conversion` — SaaS messaging, signup, activation, pricing and free-to-paid conversion.
- `premium-motion-interactions` — purposeful animation, microinteractions and motion performance.
- `landing-page-ultra-conversion` — single-goal landing pages, offer/message match, proof, forms and conversion optimization.
- `design-system-component-library` — reusable design tokens, components, variants, states and scalable UI architecture.
- `prelaunch-automatic-audit` — mandatory pre-publish audit across QA, mobile, accessibility, performance, SEO, CRO, tracking and security basics.

## Core philosophy

A website is not finished because it looks polished. It is finished when it is understandable, useful, credible, responsive, technically sound, measurable, and aligned with a business objective.

This knowledge base is written as original guidance. It is not a verbatim copy of third-party skills or proprietary training material.
