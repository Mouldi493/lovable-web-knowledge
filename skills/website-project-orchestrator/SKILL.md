# Website Project Orchestrator

Use this skill for a new website project or a major redesign. Do not use it for a tiny isolated fix.

## Mandatory kickoff

For a new website, do not start coding immediately.

First inspect all available context. Then ask only the missing discovery questions, one at a time.

Resolve:
1. Website type.
2. Primary business objective.
3. Primary audience.
4. Main offer.
5. Strongest real differentiators.
6. Primary CTA.
7. Desired brand feeling and what it must not feel like.
8. Existing assets.
9. Real proof/trust elements.
10. Competitors.
11. Geographic and SEO scope.
12. Required functionality.
13. Technical constraints.
14. Content status.
15. Deadline or launch constraints when relevant.

Skip questions already answered. Skip irrelevant questions. Use follow-ups only when they change a meaningful decision.

## Website Brief gate

Before implementation, summarize:
- website type
- primary objective
- target audience
- main offer
- differentiators
- CTA
- brand direction
- assets
- proof
- competitive context
- SEO/geographic scope
- functionality
- technical constraints
- content status
- top priorities

Then propose information architecture and execution order.

## Workflow

### 1. Strategy
Establish audience, intent, offer, primary conversion, proof, objections and business priorities.

### 2. Architecture
Define pages, navigation, hierarchy and conversion paths. Every page must have a clear purpose.

### 3. Copy
Write or improve conversion-oriented copy before polishing visuals. Use real customer language when available.

### 4. Visual direction
Choose one coherent direction. Establish typography, color, spacing, components and interaction language before multiplying sections.

### 5. Build
Follow the existing project stack when one exists. For a fresh Lovable project, keep architecture simple, typed and maintainable.

### 6. Mobile
Treat responsive design as part of the initial build.

### 7. SEO and tracking
Add what the project genuinely needs. Do not overbuild.

### 8. QA
Test the main user journey, forms, navigation, responsive behavior, console state and critical interactions.

## Default decision rules

For local services:
- prioritize trust, geographic relevance, service clarity and low-friction contact.

For ecommerce:
- prioritize product clarity, value perception, proof, variant/pack selection, shipping/returns reassurance and checkout friction.

For SaaS:
- prioritize promise, product proof, use cases, pricing clarity, signup friction and time-to-value.

For landing pages:
- keep one dominant conversion goal and remove distractions.

## Restraint
Do not load every possible technique into every project. Use the smallest set of patterns needed to solve the actual problem.
